# Заглушка Remap API 1.2

Отдельный HTTP-процесс для учебного стенда интернет-магазина. Магазин в режиме `mock` обращается к нему как к МойСклад. Это не полный Remap API и не замена тестового аккаунта.

Состояние хранится в памяти и живёт между запросами одного запуска. Перезапуск процесса возвращает начальные данные. Управляющий API не требует авторизации и не предназначен для публичного стенда.

## Запуск

Нужна Java 21.

```bash
cd remap-stub
mvn spring-boot:run
```

Порт по умолчанию — `8088`, чтобы не пересечься с модулем `intern` на `8080`.

```yaml
moysklad:
  mode: mock
  base-url: http://localhost:8088/api/remap/1.2
  token: ${MOYSKLAD_TOKEN:}
```

Проверка:

```bash
curl -s -H 'Authorization: Bearer test' -H 'Accept-Encoding: gzip' \
  http://localhost:8088/api/remap/1.2/entity/product
```

`remap.stub.required-token` пустой: принимается любой непустой `Authorization`. Если задать токен, заголовок должен быть равен `Bearer <токен>`. Без `Accept-Encoding`, содержащего `gzip`, ответ `415` и пустое тело. Без `Authorization` — `401`. Тело ответа при этом не сжимается.

| Склад | `22222222-2222-2222-2222-222222222223` | второй |

## Подмножество Remap

Базовый путь `/api/remap/1.2`.

- `POST /security/token` возвращает `access_token` = `stub-access-token` и ничего не отзывает.
- `GET /context/employee`, `GET /context/companysettings/pricetype`.
- `GET /audit` — упрощённый журнал созданий, изменений и удалений.
- `GET /report/stock/all` и `/bystore` с пагинацией; `/all/current` и `/bystore/current` одним массивом.
- `GET /entity/assortment` — товары и модификации.
- CRUD: `product`, `variant`, `productfolder`, `organization`, `store`, `counterparty`, `currency`, `pricetype`, `saleschannel`, `state`, `webhook`, `webhookstock`, `customerorder`, `demand`, `salesreturn`, `paymentin`, `paymentout`.
- `PUT /entity/demand/new` и `PUT /entity/salesreturn/new` возвращают шаблон и не сохраняют документ.
- Позиции: коллекция и одна позиция.
- `POST /entity/{type}/{id}/trash` снимает проведение отгрузки и убирает сущность из обычной выборки.
- `GET /download/{id}` отдаёт крошечный PNG. Срок ссылки не ограничен.

Документы требуют `organization` и `agent`. Модификация требует `product`. `applicable` у документа по умолчанию `true`. Массив длиннее 1000 элементов отвечает `413`. `limit` вне `1..1000` отвечает `400`.

Повтор создания с тем же `syncId` возвращает уже созданную сущность и игнорирует новое тело. Удаление по `/syncid/{id}` поддержано.

Деньги — число в копейках. `sum`, `reservedSum`, `shippedSum` считаются заглушкой. `paymentin.sum` можно передать. `payedSum` пересчитывается из `operations[].linkedSum`.

Фильтры: `=`, `!=`, `~`, `>=`, `<=`, `>`, `<` по `id`, `name`, `email`, `externalCode`, `article`, `syncId`, `archived`, `applicable`, `updated`. `search` ищет по имени. `order=field` или `order=field,desc`. Архивные скрыты, пока фильтр не упоминает `archived`. `expand` раскрывает `positions`, `agent`, `store`, `organization`, если запрос одной сущности или `limit` не больше 100.

`fields=stock` у позиции использует имена позиции, а не отчёта: `quantity` здесь физический остаток, `available` = остаток − резерв + ожидание. В коротком отчёте `quantity` — это доступное количество с учётом резерва и ожидания. `freeStock` = остаток − резерв. Это разные поля.

## Остатки

Пересчёт в заглушке синхронный.

- Проведённый заказ держит `positions.reserve` на своём складе. Резерв больше количества позиции — ошибка `17003`.
- Проведённая отгрузка уменьшает физический остаток на своём складе и уменьшает резерв заказа на `min(reserve, quantity)`, увеличивая `shipped`. Количество отгрузки больше недоотгруженного остатка заказа — `400`.
- Снятие проведения и удаление непроведённой отгрузки откатывают это движение. Удалить проведённую отгрузку нельзя (`409`), пока проведение не снято. Удалить заказ, на который ссылается отгрузка, нельзя (`409`).
- Проведённый возврат увеличивает физический остаток и не уменьшает `shipped` заказа.
- `paymentin` и `paymentout` меняют `payedSum` и не меняют остаток.
- Отрицательный остаток допускается. `inTransit` меняется только через `POST /api/stub/stock`. Закупки его не двигают.
- `POST /api/stub/stock` записывает абсолютные числа и может разойтись с документами до следующего `reset`.

Короткий отчёт: `stockType` = `stock` | `freeStock` | `quantity` | `reserve` | `inTransit`. Без `changedSince` нулевые строки скрыты, пока нет `include=zeroLines`. `changedSince` не старше 24 часов возвращает текущие значения изменившихся строк, включая нули. Это не дельта и не история.

## Вебхуки

Создание, изменение и удаление поддерживаемой сущности шлёт `POST` на включённые подписки с тем же `entityType` и `action`. В теле есть `auditContext` и `events[]` с `meta`, `action`, `accountId`. Полной сущности в теле нет. Ответ получателя ждётся 1500 мс. Неуспех записывается в журнал и не отменяет документ. Повтор той же доставки — `POST /api/stub/webhooks/redeliver`: уходит тот же `requestId`.

Заголовок `X-Lognex-WebHook-DisableByPrefix` (несколько заголовков, не список через запятую) подавляет URL, которые с него начинаются.

Подписка `webhookstock` сохраняется, но изменение остатка само уведомление не шлёт. Пачку событий можно отправить через `POST /api/stub/webhooks/emit`. Флаг `POST /api/stub/webhooks/disorder` разворачивает пачку из двух и более событий.

Новая подписка без поля `enabled` включается.

## Управляющий API

Вне `/api/remap/1.2`. Спецификация: `online-store-architecture/api/moysklad-stub-openapi.yaml`.

| Метод и путь | Назначение |
|---|---|
| `POST /api/stub/reset`, `POST /api/stub/seed` | Начальные данные, пустые сбои и журнал вебхуков |
| `GET /api/stub/faults` | Текущие правила |
| `POST /api/stub/faults` | Одно правило |
| `DELETE /api/stub/faults` | Удалить правила |
| `POST /api/stub/unavailable` | `{"enabled": true}` отвечает `503` на Remap, обработчик не вызывается |
| `POST /api/stub/stock` | Абсолютные `stock`, `reserve`, `inTransit` |
| `GET /api/stub/webhook-deliveries` | Журнал попыток |
| `POST /api/stub/webhooks/redeliver` | Повтор по `deliveryId` с тем же `requestId` |
| `POST /api/stub/webhooks/disorder` | Обратный порядок следующей пачки |
| `POST /api/stub/webhooks/emit` | Отправить пачку `events` на `url` |

Правило сбоя:

```json
{
  "method": "POST",
  "pathPattern": "/api/remap/1.2/entity/customerorder",
  "faultType": "LOSE_RESPONSE",
  "count": 1,
  "httpStatus": 500,
  "delayMs": 0,
  "code": 0
}
```

`pathPattern` — шаблон Ant. Точный путь не покрывает вложенные. Для вложенных нужен `/**`.

| `faultType` | Что происходит |
|---|---|
| `DELAY` | Пауза `delayMs`, затем обычная обработка |
| `TIMEOUT` | Пауза `delayMs` или 30 с, затем `503`. Обработчик не вызывается |
| `HTTP_STATUS` | Заданный статус и JSON `errors`. Для `429` код `1049`, если `code` равен 0. Код `1073` задаётся явно. Обработчик не вызывается |
| `CONNECTION_RESET` | Статус `500` и заголовок `X-Stub-Fault: connection-reset`. Соединение целиком не обрывается. Обработчик не вызывается |
| `LOSE_RESPONSE` | Обработчик выполняется, состояние сохраняется, клиенту уходит пустое тело |

Лимит 45 запросов за 3 секунды сам по себе не имитируется. `429` появляется только из правила сбоя.

## Чем заглушка отличается от Remap API

Эти отличия нельзя переносить на режим `real` как свойства МойСклад.

- Остаток пересчитывается сразу. В API пересчёт не мгновенный, `withRecalculate=true` есть только у короткого отчёта по складам.
- Ответ не сжимается, хотя заголовок `gzip` обязателен.
- `POST /security/token` не отзывает прежние токены.
- Аудит — плоский список, без полного контракта `/audit`.
- Нет автоматического лимита, параллельности и автоотключения доступа.
- `webhookstock` не рассылается по изменению остатка. Повтор трёх немедленных попыток и отбрасывание уведомления не моделируются: попытка одна, дальше только `redeliver`.
- Услуги, комплекты и партии в ассортимент не попадают.
- Закупки не создают `inTransit`. Отрицательный остаток не запрещён.
- Возврат не уменьшает `shipped` заказа и не разбирает себестоимость.
- Ошибка валюты `22004` не моделируется.
- `externalCode` и `article` не проверяются на уникальность. Так же и в публичной документации они не описаны как ключ идемпотентности создания.
- Ссылка `downloadHref` не протухает.
- `CONNECTION_RESET` — это статус `500` с заголовком, а не обрыв TCP.
