## SDK и спецификации

Официальный портал разработчика указывает Java SDK. На 26 ноября 2026 года документация методов SDK открывалась из репозитория https://github.com/moysklad/remap-1.2-java-sdk . Имя репозитория сверьте с актуальной ссылкой на https://dev.moysklad.ru/ : в учебных материалах также встречается `moysklad/java-remap-1.2-sdk`.

SDK и сторонняя OpenAPI-спецификация https://github.com/moysklad/api-remap-1.2-openapi-specification полезны как путеводитель по именам. Контрактом остаётся документация API. Если SDK и документация расходятся, в архитектуре фиксируется документация и версия SDK, на которой расхождение замечено.

В публичное API магазина модели SDK не переносятся.

## Что читать по архитектуре

Материалы ниже про приёмы, а не про готовое решение этого магазина. Наличие статьи не означает, что приём обязателен.

- C4: https://c4model.com/
- Модульный монолит и граница модулей: сравнение студент делает сам; стартовая точка — обзоры Simon Brown (модульный монолит и C4) и Martin Fowler о монолите и микросервисах.
- Идемпотентность API: материалы Мартина Фаулера и документация выбранного HTTP-клиента про повтор небезопасных методов.
- Transactional outbox: обзор паттерна у микросервисных архитектурных каталогов (например, microservices.io, pattern Transactional Outbox) и главы про публикацию событий после `COMMIT`.
- Inbox и идемпотентный потребитель: там же, Idempotent Consumer.
- Saga и компенсация: microservices.io, pattern Saga. Сравните с локальным процессом в одном приложении: отдельный брокер не обязателен.
- Circuit breaker: описание Мартина Фаулера, https://martinfowler.com/bliki/CircuitBreaker.html
- Повтор с экспоненциальной паузой и джиттером: различайте повтор безопасного чтения и повтор создания документа.
- PostgreSQL, блокировки строк: документация `SELECT ... FOR UPDATE` и `FOR NO KEY UPDATE` той версии, которую вы фиксируете в стеке. Обратите внимание, какую строку блокировка не видит, если продажи идут через другой канал.
- Уникальные ограничения как способ поймать гонку: документация PostgreSQL, constraints.
- OpenAPI 3.1: https://spec.openapis.org/oas/v3.1.0
- Наблюдаемость: документация OpenTelemetry по traces, metrics и logs. Подключать весь стек имеет смысл только после ADR.

Учебные тексты не заменяют раздел Remap API. Нельзя переносить в проект лимит «100 запросов за 5 секунд»: это ограничение другого API МойСклад (POS API), не Remap 1.2.

## Как конспектировать

В `docs/integration/moysklad-api.md` для каждого используемого ресурса достаточно:

- метод и путь;
- поля, которые магазин читает или пишет;
- поля только для чтения, которые нельзя присылать как команду;
- ошибка, на которую опирается сценарий;
- ссылка на раздел и дата чтения.

Копировать справочник целиком не нужно. Дословные многостраничные выгрузки документации в репозиторий не входят в результат: это и объём, и вопрос прав на текст документации. Короткая цитата поля с указанием источника допустима, если без неё термин двусмысленен (`quantity` в отчёте и `quantity` в `fields=stock`).
