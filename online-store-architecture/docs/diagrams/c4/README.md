# Диаграммы C4

Нотация C4. Исходник — PlantUML (`C4_Context`, `C4_Container`, `C4_Component`, `C4_Deployment`) или эквивалент, который преподаватель откроет без вашей машины. Картинка без исходника не принимается.

Файлы:

| Файл | Диаграмма |
|---|---|
| `system-context.puml` | System Context |
| `container.puml` | Container |
| `component.puml` | Component |
| `deployment.puml` | Deployment |

## Общие правила

- у каждого элемента имя и ответственность одной фразой;
- стрелка подписана действием и направлением данных, а не словом «использует»;
- внешние системы отличаются от контейнеров вашего контура;
- режим `mock` не рисуется как будто МойСклад отсутствует: на контексте МойСклад остаётся внешней системой, на развёртывании показаны оба адреса.

## System Context

Люди: покупатель, администратор, сотрудник МойСклад (если он меняет документы вне магазина). Системы: интернет-магазин, МойСклад, платёжная заглушка. Заглушка Remap API на контексте может быть показана как заменяемая реализация внешней системы, а не как вторая учётная система с собственной бизнес-ролью.

## Container

Внутри магазина: frontend, backend, база. Интеграционный слой виден как часть backend или как отдельный контейнер, если вы так решили в ADR. Заглушка Remap и заглушка оплаты — отдельные процессы. Брокер, кэш и сбор метрик появляются только вместе с ADR.

## Component

Компоненты backend вокруг проведения заказа и интеграции. Доменный компонент не зависит от JSON Remap. Порт и адаптер различимы. Достаточно компонентов, которые принимают решения; по одному прямоугольнику на класс не рисовать.

## Deployment

Узлы учебного стенда, переменная режима, место секрета вне репозитория, кто открывает соединение вебхука. См. `docs/architecture/deployment.md`.
