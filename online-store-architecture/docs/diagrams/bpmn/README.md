# Диаграммы BPMN

Восемь процессов. Один файл — один процесс. Допустимы PlantUML или Mermaid. Если используете Mermaid, сохраните имя из таблицы и расширение `.mmd`, а пустой `.puml` удалите, чтобы не было двух версий.

| Файл | Процесс |
|---|---|
| `catalog-sync.puml` | Синхронизация каталога |
| `stock-sync.puml` | Синхронизация остатков |
| `checkout.puml` | Оформление заказа |
| `payment.puml` | Оплата |
| `reservation.puml` | Резервирование |
| `shipment.puml` | Комплектация и отгрузка |
| `cancellation.puml` | Отмена |
| `return.puml` | Возврат |

На каждой диаграмме должны быть читаемы без текста процесса:

- участники и границы систем (пулы или дорожки);
- развилка с подписями исходов;
- параллельные ветки там, где они есть в описании, либо одна последовательная цепочка, если процесс так и задуман;
- таймер (ожидание оплаты, срок резерва, период сверки, окно повтора);
- событие ошибки;
- повтор;
- компенсация;
- конечные события успеха и отказа.

Элемент без подписи не считается. Диаграмма, на которой нет ни одного отказа, не закрывает этап.

Отмена показывает несколько допустимых точек входа или явные отказы для недопустимых точек. Возврат показывает частичное количество. Синхронизация остатков показывает полную сверку и инкремент, если вы используете оба.
