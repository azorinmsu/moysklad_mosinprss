# Автомат состояний заказа

Файл `order-state.puml` — автомат заказа витрины. Отдельные автоматы оплаты, резерва, отгрузки, возврата и синхронизации добавляйте файлами `payment-state.puml`, `reservation-state.puml`, `shipment-state.puml`, `return-state.puml`, `sync-state.puml` только если в тексте архитектуры у них собственный жизненный цикл. Пустые файлы «на будущее» не создавайте.

Исходный набор состояний можно заменить, не выбросив без объяснения промежуточные состояния, в которых процесс переживает таймаут и перезапуск: ожидание резерва, ожидание оплаты, отмена в процессе, сбой.

Для каждого перехода в сопроводительной таблице в этом файле или в `docs/business/business-processes.md`:

| Переход | Инициатор | Событие | Предусловие | Из состояний | Побочный эффект | Компенсация | Повтор |
|---|---|---|---|---|---|---|---|

Рядом — таблица соответствия состоянию витрины полей `applicable`, `state` и наличия связанных `demand`, `paymentin`, `salesreturn`. Имена состояний витрины не обязаны совпадать с именами статусов МойСклад.

Тупик, из которого нет пути в успех, отмену или `FAILED`, считается дефектом. Переход, повтор которого создаёт второй внешний документ, тоже.
