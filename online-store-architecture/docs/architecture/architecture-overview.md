# Обзор архитектуры

## Назначение системы

Кратко: что делает магазин, что остаётся в МойСклад, чем заглушка платёжной системы отличается от `paymentin`.

## Выбранный стиль

Модульный монолит или микросервисы. Один абзац решения и ссылка на ADR. Сравнение, из-за которого выбор сделан, поместите здесь целиком.

В сравнении обязаны участвовать:

- 200 одновременных чтений каталога при запрете ходить в Remap API на каждый просмотр;
- 1 000 заказов в сутки и пауза внешнего API;
- одна распределённая операция «локальный заказ + документ учёта»;
- учебный контур поставки: сколько процессов нужно поднимать, чтобы пройти сценарий заказа.

Дополнительные сервисы (кэш, брокер, отдельный синхронизатор) перечисляются только если без них выбранный стиль не выполняет нефункциональные требования. Для каждого — ссылка на ADR.

## Потоки данных

Опишите словами и сошлитесь на диаграммы C4:

- чтение каталога;
- оформление и резерв;
- оплата;
- отгрузка и возврат;
- входящий вебхук;
- сверка.
