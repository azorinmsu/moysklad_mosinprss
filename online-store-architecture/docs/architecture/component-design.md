# Компоненты

Диаграмма: `docs/diagrams/c4/component.puml`.

Опишите компоненты backend, которые принимают решения. Полный список классов не нужен.

## Обязательные границы

| Компонент | Ответственность | Чего компонент не делает |
|---|---|---|
| Каталог и поиск | | не вызывает Remap на запрос витрины |
| Корзина | | не проводит документы учёта |
| Заказы | | не собирает JSON Remap |
| Оплата | | не подменяет `paymentin` |
| Интеграционный порт МойСклад | | не ветвится по режиму `mock`/`real` |
| Адаптер Remap | | не содержит правил витрины |
| Приём вебхуков | | не выполняет долгую обработку внутри ответа 1500 мс |
| Синхронизация | | не становится источником истины остатка, если ADR решил иначе |
| Проекция остатков | | |

Если порт и адаптер у вас названы иначе, сохраните смысл: домен вызывает порт, реализация порта одна на процесс, URL и токен приходят извне.

## Преобразование моделей

Таблица полей, которые пересекают границу. Пример состава строк, значения заполняете вы:

| Понятие магазина | Поле Remap API | Преобразование | Направление |
|---|---|---|---|
| Цена в валюте витрины | `salePrices[].value` или цена позиции | минимальные единицы | |
| Позиция заказа | `positions[].assortment` | ссылка `meta` на `product` или `variant` | |
| Резерв | `positions[].reserve`, `applicable` | | |
| Оплата учёта | `paymentin.operations[].linkedSum` | | |
| Статус витрины | `state` и набор документов | таблица отображения, не равенство имён | |

## Зависимости

Кто кого вызывает в сценариях оформления, отмены и синхронизации. Цикл «домен → адаптер → домен» нужно либо убрать, либо объяснить.
