# Доменная модель

Заполняет студент. Каркас ниже фиксирует только состав разбора.

## Контекст

Интернет-магазин и МойСклад — две модели. Опишите границу: какие понятия существуют только на витрине, какие только в учёте, какие сопоставляются.

## Понятия учёта

Для каждого ключевого слова из раздела 4.1 задания: определение своими словами, владелец данных, какие документы его меняют, что витрина хранит у себя.

`product`, `variant`, `productfolder`, `assortment`, `store`, `organization`, `counterparty`, `customerorder`, `demand`, `salesreturn`, `paymentin`, `state`, `saleschannel`, `pricetype`, отчёт остатков.

Отдельно отметьте сущности, которые вы не включаете в минимальный контур (`service`, `bundle`, `consignment`, розница), и правило, если такая ссылка всё же придёт в `assortment` или в позиции документа.

## Понятия витрины

Покупатель, сессия, корзина, локальный заказ, локальный статус, платёж заглушки, резерв витрины (если он есть отдельно от `reserve`).

## Правила, которые модель обязана выразить

- Товар с модификациями: что именно продаётся.
- Несколько типов цен: какой `pricetype` показывает витрина.
- Несколько складов: какой остаток виден покупателю.
- Архив и снятие с продажи.
- Расхождение цены корзины и цены учёта.
- Другой канал на том же складе.

## Вне модели

Перечислите сознательно отложенное: маркировка, серии, комплекты, бонусы, несколько организаций. Для каждого — почему сценарии задания без этого замкнуты.
