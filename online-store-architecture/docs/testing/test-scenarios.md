# Тестовые сценарии

Заполните по шаблону [`../../templates/test-case-template.md`](../../templates/test-case-template.md).

Минимальный набор идентификаторов, который должен появиться:

| Идентификатор | Смысл | Уровень | Режим |
|---|---|---|---|
| TC-CAT-001 | Карточка отдаётся из локальной базы | integration | mock или без МойСклад |
| TC-CAT-002 | Архивный товар не продаётся | integration | mock |
| TC-SYNC-001 | Первичная загрузка нескольких страниц | integration | mock |
| TC-SYNC-002 | Сбой на второй странице не портит уже принятые данные | fault-injection | mock |
| TC-SYNC-003 | Догон после простоя дольше 24 часов | integration | mock |
| TC-STOCK-001 | Продажа по выбранному `stockType` | integration | mock |
| TC-STOCK-002 | Чужое списание видно после сверки | integration | mock |
| TC-ORDER-001 | Успешное оформление | e2e | mock |
| TC-ORDER-002 | Недостаточное количество | e2e | mock |
| TC-ORDER-003 | Две параллельные покупки последней единицы | concurrency | mock |
| TC-ORDER-004 | Повтор оформления | concurrency | mock |
| TC-ORDER-005 | Цена изменилась | e2e | mock |
| TC-INT-001 | Создание заказа в учёте | contract | mock и real на узком наборе |

| TC-INT-003 | Повтор вебхука | integration | mock |

Дополнительные сценарии добавляйте, если их требует ваш ADR. Существующие строки не удаляйте: если сценарий неприменим к выбранной архитектуре, напишите, какое решение делает его бессмысленным, и замените ожидаемым результатом вашей модели.
