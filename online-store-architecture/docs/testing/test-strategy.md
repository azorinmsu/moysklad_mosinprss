# Стратегия тестирования

Код тестов на этом этапе не пишется. Стратегия должна позволить перенести сценарии в автотесты без новых архитектурных решений.

## Уровни

| Уровень | Что доказывает | Где исполняется | Чего не доказывает |
|---|---|---|---|
| Unit | | домен без HTTP МойСклад | |
| Integration | | магазин и его база, внешний контур заменён заглушкой по HTTP | |
| Contract | | заглушка против тестового аккаунта | |
| End-to-end | | витрина, магазин, заглушка оплаты, заглушка Remap | |
| Load | | числа из NFR, включая запрет читать каталог из API | |
| Concurrency | | последняя единица, повтор оформления, отмена против отгрузки | |
| Fault injection | | отказы управляющего API заглушки | |

## Режим mock

Тесты поднимают заглушку отдельным процессом. Проверяются остаток после резерва, частичная отгрузка, частичный возврат, повтор `requestId`, сохранение документа без HTTP-ответа, 429 и таймаут. Mockito внутри процесса магазина может использоваться в unit-тестах домена и не считается выполнением этого режима.

## Режим real

Только выделенный тестовый аккаунт и отдельный сотрудник интеграции. Рабочий аккаунт не используется. Перед прогоном фиксируется, какие документы тест создаёт и как их найти для удаления (`externalCode` или `syncId` тестового прогона). Прогон не вызывает `POST /security/token`, если это отзывает токен, нужный стенду. Недоступность тестового аккаунта не заменяется боевым.

Контрактный тест сравнивает узкий набор запросов. Несравнимые поля перечислены. Расхождение остатка после проведённой отгрузки — дефект заглушки, даже если JSON-схема совпала.

## Нагрузка и лимиты

Нагрузочный сценарий каталога обслуживается локальной базой. Поток запросов к Remap API в этом сценарии отсутствует. Отдельный сценарий оценивает синхронизацию 100 000 позиций относительно бюджета запросов. Он может быть расчётным, если живой прогон на 100 000 записей тестового аккаунта невозможен: тогда сказано, что измерено, а что посчитано.

## Критерий готовности стратегии

По каждому FR уровня заказа, оплаты, отмены, возврата и синхронизации назван уровень теста. Fault injection покрывает таблицу из `docs/integration/error-handling.md`.
