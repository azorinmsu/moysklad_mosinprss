# Заглушка Remap API

## Роль

Отдельный процесс. Магазин обращается к нему как к `base-url` режима `mock`. Внутри магазина нет ветки, которая подменяет HTTP заглушки моками фреймворка.

Состояние заглушки переживает следующий запрос того же сценария: созданный документ виден в GET, проведённая отгрузка меняет отчёт остатков по правилам, которые вы зафиксировали в доменной модели.

## Состав

Разделите два контракта:

1. Имитация подмножества `/api/remap/1.2` — поведение как у документации на выбранных путях.
2. Управляющий API вне этого префикса — фикстуры и отказы. Спецификация: [`../../api/moysklad-stub-openapi.yaml`](../../api/moysklad-stub-openapi.yaml).

## Поведение учёта

Опишите, как заглушка пересчитывает остаток, резерв и ожидание. Это упрощённая модель, но она должна быть достаточной для сценариев задания: резерв не выше количества позиции, частичная отгрузка, частичный возврат, снятие проведения, платёж не меняет `stock`. Если полное правило МойСклад вы сознательно упростили, ограничение стоит в матрице совместимости.

Повтор создания с тем же `syncId` возвращает уже созданную сущность, если этот механизм входит в ваш контракт.

## Контрактная проверка против реального API

Какие запросы выполняются и на заглушке, и на тестовом аккаунте. Какие поля исключены из сравнения. Кто запрещает запуск этой проверки с токеном рабочего аккаунта.

Заглушка не обязана реализовывать весь Remap API. Любой путь, которого нет в матрице, для магазина не существует: адаптер не должен его вызывать.
