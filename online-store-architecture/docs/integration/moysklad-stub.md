# Заглушка Remap API

Этот документ описывает уже запущенный процесс [`remap-stub`](../../../remap-stub/README.md). Его не переписывают и не заменяют своим проектом заглушки. Решения магазина записываются в соседних файлах.

## Роль

Отдельный процесс на порту `8088`. Магазин в режиме `mock` ставит `base-url: http://localhost:8088/api/remap/1.2` и ходит туда по HTTP. Ветки `if (mode == mock)` в доменной логике нет. Mockito внутри процесса магазина эту заглушку не заменяет.

Состояние живёт между запросами одного запуска: созданный документ виден в GET, проведённая отгрузка сразу меняет отчёт остатков. Перезапуск или `POST /api/stub/reset` возвращает начальные данные.

## Два контракта

1. Имитация подмножества `/api/remap/1.2`. Состав и отличия от документации — в [`api-compatibility-matrix.md`](api-compatibility-matrix.md) и в README заглушки.
2. Управляющий API вне этого префикса. Спецификация: [`../../api/moysklad-stub-openapi.yaml`](../../api/moysklad-stub-openapi.yaml). Авторизации у него нет.

## Поведение учёта

Пересчёт синхронный, в отличие от реального API.

- Проведённый `customerorder` держит `positions.reserve` на складе заказа. Резерв больше количества — `17003`.
- Проведённый `demand` уменьшает физический остаток на складе отгрузки и резерв заказа на `min(reserve, quantity)`, увеличивая `shipped`. Частичная отгрузка — меньшее `quantity` позиции.
- `PUT /entity/demand/new` и `PUT /entity/salesreturn/new` возвращают шаблон и не сохраняют документ.
- Проведённый `salesreturn` увеличивает физический остаток и не уменьшает `shipped` заказа.
- `paymentin` и `paymentout` пересчитывают `payedSum` из `operations[].linkedSum` и не меняют `stock`.
- Повтор создания с тем же `syncId` возвращает уже созданную сущность и не применяет новое тело.
- `POST /api/stub/stock` записывает абсолютные остатки и может разойтись с документами до `reset`.

В отчёте `quantity` — доступное количество. В объекте `fields=stock` у позиции `quantity` — физический остаток. Это разные поля и в заглушке, и в документации.

## Отказы управляющего API

| Возможность | Зачем сценарию | Вызов |
|---|---|---|
| Сброс состояния | изолировать прогон | `POST /api/stub/reset` |
| Загрузка тестовых данных | тот же набор, что после старта | `POST /api/stub/seed` |
| Задержка | уложить вызов в таймаут клиента частично | `POST /api/stub/faults`, `faultType=DELAY` |
| HTTP 429 | код `1049` по умолчанию, `1073` через `code` | `faultType=HTTP_STATUS`, `httpStatus=429` |
| HTTP 500 и 503 | отказ без изменения состояния | `faultType=HTTP_STATUS` |
| Обрыв соединения | приближение: `500` и заголовок `X-Stub-Fault: connection-reset`, обработчик не вызывается | `faultType=CONNECTION_RESET` |
| Таймаут | пауза, затем `503`, обработчик не вызывается | `faultType=TIMEOUT` |
| Повтор вебхука с тем же `requestId` | идемпотентность приёма | `POST /api/stub/webhooks/redeliver` |
| Доставка событий не по порядку | пачка из двух и более событий разворачивается | `POST /api/stub/webhooks/disorder`, затем обычное изменение или `emit` |
| Временная недоступность | все вызовы Remap отвечают `503` | `POST /api/stub/unavailable` |
| Документ сохранён, HTTP-ответ не отдан | клиент не видит тело, сущность уже создана | `faultType=LOSE_RESPONSE` |

`pathPattern` — шаблон Ant. Точный путь не покрывает вложенные ресурсы.

Лимит запросов сам не имитируется. Окно `429` включается правилом сбоя.

## Что студенту всё равно проектировать

Платёжная заглушка в этот процесс не входит. Её контракт описывается отдельно и не выдаётся за Remap API.

Контрактная сверка с тестовым аккаунтом остаётся частью стратегии тестирования магазина. Сравниваются узкие запросы. Заранее несравнимы сгенерированные `id`, `name` документа, `moment`, `updated` и временные `downloadHref`. Расхождение «остаток ещё не пересчитан» на реальном API — свойство МойСклад. В заглушке остаток меняется сразу, поэтому тот же сценарий на тестовом аккаунте может временно показать прежний `stock`. Это не повод менять доменное правило магазина.

Путь, которого нет в матрице, магазин не вызывает. Комплекты, услуги и партии заглушка не создаёт; правило витрины на случай такого ассортимента в реальном API всё равно записывается.
