Отдельно отметьте вызовы, которых в API нет, и чем они заменены. Ожидаемые пробелы постановки: отмена как единый метод, резерв как отдельный ресурс, возврат денег платёжного шлюза, восстановление из корзины, повторная выдача потерянного вебхука.

## Протокол

- заголовок `Accept-Encoding: gzip` и реакция на 415;
- пагинация `limit`/`offset`/`nextHref` и молчаливый пропуск `expand` при `limit` больше 100;
- одно значение `fields`;
- денежные величины в минимальных единицах;
- формат даты-времени и часовой пояс аккаунта;
- структура `errors`.

## Лимиты в цифрах вашей схемы

Приведите бюджет запросов за 3 секунды, параллельность 5/20, вес расширенного отчёта, пороги автоотключения. Рядом — оценка вашей схемы из нефункциональных требований: укладывается ли обычный режим и укладывается ли догон после простоя.

## Вебхуки и аудит

Для каждого подписчика: `entityType` или `webhookstock`, `action`, `diffType`, что делается за 1500 мс, где фиксируется `requestId`, чем закрывается дыра после исчерпания попыток доставки.
