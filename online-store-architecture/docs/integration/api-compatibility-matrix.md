# Матрица совместимости заглушки с Remap API 1.2

Матрица заполнена по процессу `remap-stub`. Студент её не проектирует. Новую строку можно добавить только если путь есть в официальной документации и магазин действительно его вызывает. Пути вне таблицы для адаптера не существуют.

Дата сверки документации, на которую опирается заглушка: 26 ноября 2026, репозиторий `moysklad/api-remap-1.2-doc`, ветка `pre_release`.

| Бизнес-операция | Эндпоинт Remap API | Метод HTTP | Что делает заглушка | Ограничение относительно API |
|---|---|---|---|---|
| Получить товары постранично | `/entity/product` | GET | `meta.size` — общее число, `nextHref` при продолжении | Фильтры только из README заглушки. `expand` глубже одной ссылки и `fields` вместе с большим `limit` не повторяют все запреты API |
| Получить модификации | `/entity/variant` | GET | Модификация ссылается на `product` | Характеристики есть у начальной «Футболка Красный», произвольные характеристики при создании сохраняются как JSON |
| Получить группы товаров | `/entity/productfolder` | GET | Группа «Каталог» | Дерево из одной группы |
| Получить типы цен | `/context/companysettings/pricetype` | GET | Массив типов цен | Нет полного контракта настроек компании |
| Получить склады и организацию | `/entity/store`, `/entity/organization` | GET | Два склада и одна организация | Юрлица и склады не связаны ограничениями API |
| Найти или создать контрагента | `/entity/counterparty` | GET, POST | Фильтр по `email`, создание с `email` и `phone` | Уникальность почты и телефона не проверяется. Поиска «найти или создать» одним вызовом в API нет |
| Создать заказ с позициями и резервом | `/entity/customerorder` | POST | `organization` и `agent` обязательны, `applicable` по умолчанию `true`, резерв держится на складе | Ошибка `17003`, если резерв больше количества. Другие проверки проведения урезаны |
| Повторить создание после потери ответа | `/entity/customerorder` | POST | Тот же `syncId` возвращает прежнюю сущность | Новое тело игнорируется. Заголовка `Idempotency-Key` нет и в API |
| Изменить заказ | `/entity/customerorder/{id}` | PUT | Замена коллекции `positions` целиком, `shipped` прежней позиции сохраняется | Клиентский `shipped` игнорируется |
| Снять проведение или отменить заказ | `/entity/customerorder/{id}` | PUT | `applicable=false` снимает резерв. Статус `state` сам остаток не двигает | Отмена как отдельной операции нет. Удаление заказа с отгрузкой — `409` |
| Получить шаблон отгрузки | `/entity/demand/new` | PUT | Шаблон по `customerOrder` с недоотгруженным количеством | Документ не сохраняется |
| Создать отгрузку, в том числе частичную | `/entity/demand` | POST | Проведённая отгрузка уменьшает остаток и резерв, увеличивает `shipped` | Пересчёт мгновенный. Проведённая отгрузка без склада — `412`. Удаление проведённой — `409` |
| Создать возврат по отгрузке | `/entity/salesreturn` | POST | Проведённый возврат увеличивает физический остаток. Шаблон: `PUT /entity/salesreturn/new` | `shipped` заказа не уменьшается. Себестоимость и возврат без основания не разобраны |
| Создать входящий платёж | `/entity/paymentin` | POST | `operations[].linkedSum` увеличивает `payedSum` заказа, отгрузки или возврата | Остаток не меняется. Ошибка валюты `22004` не моделируется. `cashin` нет |
| Зафиксировать возврат денег | `/entity/paymentout` | POST | Проведённый документ добавляет `linkedSum` в `payedSum` связанных операций, как и `paymentin` | Знак исходящей оплаты не отличается от входящей. Это документ учёта, не ответ платёжной заглушки |
| Прочитать остатки | `/report/stock/all`, `/report/stock/all/current` | GET | `stock`, `reserve`, `inTransit`, `quantity`, `freeStock` | Короткий отчёт без пагинации. Нулевые строки скрыты без `include=zeroLines` или `changedSince` |
| Прочитать остатки по складам | `/report/stock/bystore`, `/report/stock/bystore/current` | GET | Строка на пару ассортимент–склад | `withRecalculate` не меняет поведение: пересчёт и так синхронный |
| Изменения остатков с момента | те же current-отчёты, параметр `changedSince` | GET | Текущие значения изменившихся строк, окно 24 часа | Не дельта и не история. Удалённые за окно не выделены отдельно |
| Подписать вебхук сущностей | `/entity/webhook` | POST, GET, PUT, DELETE | Уведомление при CREATE, UPDATE, DELETE подходящей сущности | Одна попытка, таймаут 1500 мс. Трёх немедленных повторов API нет. Тело без полной сущности |
| Подписать вебхук остатков | `/entity/webhookstock` | POST, GET, PUT, DELETE | Подписка сохраняется | Само изменение остатка уведомление не шлёт. Пачку даёт только управляющий `emit` |
| Прочитать сущность по ссылке из вебхука | `meta.href` | GET | Обычное чтение сущности | После DELETE сущность уже может отсутствовать, GET вернёт `404` |
| Восстановить пропущенные изменения | `/audit`, фильтр `updated` | GET | Упрощённый аудит и фильтр по `updated` | Аудит не совпадает со схемой API. Повтора недоставленного вебхука в API нет |
| Прочитать статусы документа | `/entity/customerorder/metadata` и сущности `state` | GET | Два статуса заказа в начальных данных | `stateType` не двигает остаток. Метаданные остальных документов пустые, пока статус не создан |
| Скачать изображение | `/download/{id}` | GET | Маленький PNG | `downloadHref` не протухает. Коллекция `images` у товара есть в JSON, отдельный CRUD изображений не реализован |
| Выпустить токен | `/security/token` | POST | Всегда `stub-access-token` | Прежние токены не отзываются. Для стенда этот вызов не нужен |

Управляющие пути `/api/stub/**` в таблицу не входят.

В ассортименте нет `service`, `bundle`, `consignment`. Розничные `retaildemand` и `retailshift` не реализованы.
