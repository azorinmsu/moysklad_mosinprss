# Конкурентный доступ к данным магазина

Этот документ — про PostgreSQL магазина. Внешний канал продаж разобран в [`../integration/consistency.md`](../integration/consistency.md): здесь нужно показать границу, за которой строковая блокировка перестаёт действовать.

Для каждой выбранной меры укажите проблему из двенадцати, которую она закрывает, и проблему, которую она не закрывает.

Рассмотрите применимость, даже если часть механизмов будет отклонена:

- оптимистическая блокировка версией строки;
- `SELECT FOR UPDATE`;
- `SELECT FOR NO KEY UPDATE`;
- один `UPDATE ... WHERE available >= :qty`, который меняет проекцию только при достаточном количестве;
- уникальный ключ идемпотентности;
- уникальная пара «локальный заказ — id документа МойСклад».

Напишите уровень изоляции транзакции оформления и почему его хватает вместе с выбранным оператором. Если две транзакции читают остаток до обновления, покажите, какой из приёмов не даёт обеим успешно списать последнюю единицу.

Укажите порядок блокировок, если заказ и остаток блокируются вместе, чтобы не получить взаимное ожидание.

Повторная обработка outbox и inbox: какой уникальный ключ делает повтор безопасным.
